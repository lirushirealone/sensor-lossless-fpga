# 可复用工程技能

本目录从真实开发失败与测量中提炼技能。原始交互见report/ai_records/records.md，案例c01至c10；验证证据见evidence/collaboration。下面区分已执行的检查、历史板测和仍需迁移验证的范围。

| 技能 | 适用范围 | 使用方法 | 已验证效果 | 失效条件 |
|---|---|---|---|---|
| checksum_audit.py | 任意题目或板卡的文件交付清单 | python skill/checksum_audit.py <root> <manifest.json> | 新目录、不同内容的两组合法清单通过；文件篡改、丢失和两类越界清单被拒绝，见check_examples.py及evidence/skill_validation.json | 清单不可信、校验后文件改变，或需要数字签名认证 |
| dma_failure_checklist.md | PYNQ与AXI DMA的缓冲生命周期和恢复排查 | 先填写目标Overlay、IP、字宽、BTT、缓存属性和所有权，再按状态排查 | 本工程模拟故障测试、历史板卡恢复及双缓冲结果持有检查，见c03/c07 | 未核对寄存器/IP版本，复位未确认或其他进程仍拥有设备 |
| timing_review.md | CPU与FPGA重叠任务的计时与优化选择 | 先画每个计时器的起止，再做插桩扰动和无插桩配对 | c01/c02/c06纠正纯DMA归因、初始化假设和回传缩小即提速的推断 | 更换输入、边界、工具或频率却直接比较百分比 |
| prompt_workflow.md | 软硬件划分、故障诊断和复现审查 | 用模板填写真实约束，要求模型返回证据与可验证条件 | 对应c01至c10的已观察流程；模板是事后提炼，未声称在陌生题目上全部验证 | 输入信息不完整、模型编造测量或跳过验收 |

## 从哪里总结

c01的计时纠错导出区间定义规则；c02的消费者诊断导出先测初始化与返回复制；c03导出自有快照和先复位后释放；c04/c05导出回绕与失败频率必须保留；c06导出先算BTT最坏容量并测接收侧成本；c07/c09导出稳定载荷比较及实际字节清单核验；c08导出系统统计与进程映射分开观察；c10导出独立安装和迁移检查。不是把新的提示词模板冒充开发时的原始输入。

## 在别的PYNQ题目上怎么用

图像滤波、频谱处理或其他AXI流加速器可以复用DMA所有权、缓存维护、异常恢复和测量工作流；按新IP修改字宽、输出上界、TLAST、频率、寄存器和黄金参考。checksum_audit.py不依赖PYNQ，可以直接用于其他目录。DMA清单是可迁移的方法，尚未在第二种实体板卡或陌生队伍的新题目中验收，不宣称已经取得通用PYNQ额外加分。

## 自检

运行python skill/check_examples.py验证通用清单技能的正反例，运行python tools/check_collaboration.py核对交互记录及历史证据指纹。前者使用临时目录，不接触板卡；这两项不产生新的硬件性能数据。
