# 软硬件重叠任务的计时审查

适用于PYNQ的CPU准备、DMA、PL计算和CPU编码可能重叠的程序。由真实案例c01、c02、c06、c07提炼。目标是避免从边界不一致的计时器推出错误的瓶颈或收益。

1. 为每个计时器写出起止事件、单位、时钟域和包含的操作。例如device total从收数到输出，不是纯匹配；matcher work也可能包含清表和控制。CPU submit/wait不能直接当作总线搬运。
2. 画出嵌套与重叠关系。只在互斥且边界相同的区间中求和；不能用DMA调用区间减PL计数推导纯DMA。各区间中位数的和也不等于总时间中位数。
3. 冻结同一输入、完整输出、参数、工具、实际时钟及软件版本；只改变一项。先全量还原核对，再计时。代码减少复制时仍检查旧结果在复用后有效。
4. 微基准单独测初始化、参数/令牌检查、tally、Huffman、返回值构造与分配。加计时桩的版本另做正常/插桩配对，记录干扰；微基准仅用于定位，不能直接换算整机节省。
5. 用一次热身和多轮交替顺序测完整入口，记录首块延迟、尾块、内存以及是否发生输出背压。纯ARM使用相同输入准备；明确加载、I/O、SSH和独立解码是否计入。
6. 保留否定结果与资源代价。紧凑令牌若先解回uint32再编码，可能抵消传输收益；提频若不通过完整时序，不得上报目标频率。

已验证观察：c02中初始化/释放仅占旧消费者约0.9%至1.8%，直接字节返回才是该轮优先项；c06插桩使完整入口慢约5.52%至10.20%，分组紧凑原型少47.69%回传字节，但接收侧CPU区间增加27.22%至34.60%。这些数字限定于相应历史负载和边界，不能预测任意新题目的收益。详见evidence/collaboration中的历史报告与核验。

失效条件：定时器未覆盖同一事件、频率使用请求值而非实际值、把旧日期测量当作新版本、样本/块长/候选不同而称同算法加速。迁移新板卡后必须重新确认计数器语义和全部边界。
