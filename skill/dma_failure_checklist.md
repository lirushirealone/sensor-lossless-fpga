# PYNQ DMA故障定位与恢复

适用于存在可核实的AXI DMA生命周期的工程。来源为c03、c07、c09及当前软件的模拟故障测试；已在本PYNQ-Z2设计进行历史恢复测试，尚未独立验证其他实体板卡。

## 迁移前填写

记录板卡及器件、PYNQ版本、Overlay和hwh指纹、MM2S/S2MM的IP名称与版本、AXI字宽、BTT位宽、每块最大输入/输出字节、TLAST含义、缓存一致性属性、复位完成条件和唯一设备拥有者。不得直接照搬本工程IP名或地址。

## 触发条件和顺序

触发包括超时、CRC或元数据失败、长度/序号不符、重复槽、关闭时仍有DMA、消费者异常及中断。

1. 保存错误发生前后的状态、长度和序号，区分halted、idle及error；一个busy布尔量不能代替硬件状态。
2. 按最坏不可压缩输入算容量；核对字节与采样点单位、输入字宽、BTT、TLAST、实际输出长度及元数据CRC。8块8192点的32位命令输入已经超过18位BTT，不能只扩大CMA。
3. 发送前flush，完成后invalidate；输入快照和返回字节由调用者拥有。消费者仍在使用时不得复用原CMA视图，也不能以只读view代替生命周期隔离。
4. 故障后停止新提交，使整个会话失效；两个引擎均尝试复位。确认复位清除和安全状态后才释放活动缓冲。复位失败时保留视图和物理缓冲，不强行free。
5. 部分输出保留为失败状态；不生成成功报告。重新加载后用固定黄金样例核对原值、CRC、长度、通道总数和序号，再恢复使用。

## 可执行验证入口

python tools/run_tests.py运行当前统一协议和调度的19项软件测试。重点见runtime/research/test_unified.py；其他原有test_lz77_pipeline.py与test_lz77_batch2.py还覆盖过期ticket、复位失败不释放、迟到完成和下一笔取消。模拟测试说明协议和生命周期行为，不能替代真实DMA时序或板测。

历史硬件与三例复跑日期见evidence/release_checks.json；c03记录下一笔尚未完成时ARM已开始编码上一块，c07记录两路故障和对照修正。本次技能整理不重新操作板卡，不声称所有跨板场景已经通过。

失效条件：不同DMA/VDMA或scatter-gather语义、未识别的其他设备拥有者、复位失败、错误的缓存属性、跨线程操作未经验证、未知硬件仍引用缓冲。这时应回到平台手册和独立测试，而非绕过释放保护。
